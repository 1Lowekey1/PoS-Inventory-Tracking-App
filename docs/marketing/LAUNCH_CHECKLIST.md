# Launch Checklist

## 1–2 weeks before

**Product**
- [ ] Final version published to GitHub Pages ([Release Process](../internal/RELEASE_PROCESS.md))
- [ ] All edge-case tests pass at `/tests/`
- [ ] Hands-on checks from [TESTING.md](../../TESTING.md) done on at least one phone and one tablet/laptop
- [ ] Ran at least one real event with the release (or a full practice event)
- [ ] Offline install tested: install → airplane mode → open → sell

**Material**
- [ ] Screenshots taken on a real device with sample data ([Social Media Kit](SOCIAL_MEDIA_KIT.md) checklist)
- [ ] 15–30 s video recorded ([Demo Script](DEMO_SCRIPT.md))
- [ ] One-pager filled in and exported to PDF, with a QR code to the link
- [ ] Launch announcement placeholders filled ([Launch Announcement](LAUNCH_ANNOUNCEMENT.md))
- [ ] Contact channel decided (page, email or Messenger) and added everywhere
- [ ] Docs links checked: README, Quick Start, FAQ, User Guide

**Support**
- [ ] [Support Playbook](../internal/SUPPORT_PLAYBOOK.md) read; reply templates ready
- [ ] A way to collect feedback (form, comments, DMs) and somewhere to log it

## Launch day

- [ ] Post the long announcement on your page
- [ ] Share the medium version in 2–3 relevant groups (check each group's rules first)
- [ ] Post Day 1 from the social kit
- [ ] Pin the post; add the link to your bio
- [ ] Be available to answer questions for the first few hours

## First 2 weeks

- [ ] Post days 2–5 from the social kit
- [ ] Reply to every question within a day
- [ ] Log every bug report with steps to reproduce (Support Playbook format)
- [ ] Note the most-asked questions and add them to the [FAQ](../customer/FAQ.md)
- [ ] Ship fixes as small releases (bump `VERSION`, update [Release Notes](../customer/RELEASE_NOTES.md))

## After a month

- [ ] Review feedback: what do people use, what's confusing, what's missing?
- [ ] Update [Known Limitations & Roadmap](../internal/LIMITATIONS_AND_ROADMAP.md)
- [ ] Ask happy users (with permission) for a short quote or a photo of their setup
